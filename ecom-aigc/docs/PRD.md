# PRD — Ecom AIGC Content Lab（电商 AIGC 内容中台）

## 1. 背景与目标（产能 + 转化）
**背景**
- 电商/美妆类目 SKU 多、上新快、投放素材需求高，运营/投放同学需要持续产出“标题+卖点+详情+短视频脚本”。
- 纯人工写作成本高且不稳定；AIGC 可显著提效，但存在合规风险与幻觉风险（医疗化承诺/夸大宣传/成分功效编造）。

**目标**
- 产能：将单商品的素材生成时间从“人工多分钟”降低为“秒级生成多版本”。
- 转化：通过多版本生成 + 评分选优，提升“更想点击/更想购买”的版本命中率。
- 风控：提供“输出规范 + 合规规则 + 事实约束 + 回归评测”，让生成可控、可上线。

**非目标**
- 不做真实投放归因闭环（CTR/CVR 真实线上数据），本项目使用规则评分与人工偏好作为 proxy。

---

## 2. 用户与使用场景
**核心用户**
- 商家/品牌方：希望快速生成商品页素材与投放文案。
- 投放/增长：需要多版本素材 A/B，快速挑选可发布版本。
- 运营：需要可复用的文案规范、类目词库与风险提示。

**典型场景**
- 上新：批量生成标题/卖点/详情/脚本 → 选优 → 导出投放素材包。
- 风控审核：自动提示违规词/医疗化表达 → 退回改写 → 再评测。
- 迭代：基于人偏好与回归评测，持续优化生成策略/Prompt/规则。

---

## 3. 产品流程（生成-审核-选优-导出-回流）
1) 选择输入：类目 → 商品（product_id）→ 生成版本数  
2) 生成：基于 FACT_SHEET（事实表）与类目关键词生成多版本内容  
3) 自动评测：合规（policy）/关键词覆盖（SEO/类目词）/可读性（长度与重复率）  
4) 选优：对比看板输出“推荐版本”与失败原因（违规/缺词/过长/过短）  
5) 导出：一键导出投放素材包（JSON/TXT）  
6) 回流：人偏好数据（问卷 proxy）→ 迭代日志（ITERATION_LOG）→ 策略更新

---

## 4. 关键设计
### 4.1 数据与事实约束（防幻觉核心）
- 构建 `product_facts.csv`（事实表）与 `reviews.csv`（评论表）
- 生成时 **仅允许引用 FACT_SHEET 信息**，缺失则输出“未明确说明/不输出该点”
- 支持抽样评论证据（review evidence）用于解释与风控

### 4.2 输出规范（可控/可评测）
- 标题：≤30字（或 ≤60英文字符）；必须包含 1–2 个类目关键词
- 卖点 bullets：5条；每条≤20字；至少2条来自高频词
- 详情：按结构输出（痛点-解决-证据-适用人群-注意事项）
- 15秒脚本：3镜头 + 旁白 + 画面要点

### 4.3 合规规则（商业化必备）
- 规则文件：`docs/policy_rules.json`
- 禁用词：最强/根治/医美级/治疗/处方/替代药物等
- 风险提示：过敏/刺痛/红肿/不适等触发“注意事项”建议

### 4.4 评测体系（指标化）
- Fact consistency（事实一致）：不编造成分/功效/认证
- Brand tone（风格一致）：简洁口语、平台可用
- Readability（可读性）：长度/重复率
- Keyword coverage（关键词覆盖）：类目词命中数
- Policy（合规性）：违规命中次数与严重度

---

## 5. 指标（面试要讲清楚）
- 产能：单商品生成 N 个版本的耗时；批量生成吞吐（products/min）
- 违规率：violations_cnt / total_variants（越低越好）
- 偏好提升：人评 win-rate（或 proxy 选择率）
- 成本：人工时间节省；（如接入 API）token 成本估算
- 时延：生成耗时 + 评测耗时（端到端）

---

## 6. 风险与对策
- 合规风险：医疗化/夸大 → policy_rules + 自动拦截 + 改写建议
- 幻觉风险：编造成分/功效 → FACT_SHEET 约束 + “未明确说明”策略
- 品牌调性不一致：模板化输出 + tone 规则 + 回归评测
- 数据覆盖不足：sample 数据用于 demo；本地可接入全量数据
